# ASSET_PIPELINE.md — Replacing Procedural Meshes with AI-Generated Assets

> Generated by `npm run gen-pipeline` from the live registries (`src/registries/*`). Do not hand-edit prompts here; edit the
> `assetPrompt` fields instead and regenerate.

The game is **100% playable with zero external assets** — every kart, kid, weapon, shield, item and obstacle has a
`proceduralFallback(THREE)` builder (primitive geometry + `MeshToonMaterial`). Drop a production `.glb` into
`public/assets/models/<id>.glb`, run `npm run validate-assets`, and the game swaps it in automatically (the validator writes
`public/assets/models/manifest.json`, which `AssetManager.js` reads at boot). Anything missing or failing validation keeps its fallback.

## 0. Workflow
1. Generate a model with [Meshy AI](https://www.meshy.ai/) (text-to-3D, *Low Poly* + PBR off) or [Tripo3D](https://www.tripo3d.ai/) using the prompt below.
2. Fix up in Blender (or the vendor's editor): origin, forward axis, node names (see §1), triangle budget.
3. Export **glTF Binary (.glb)** → `public/assets/models/<id>.glb`.
4. `npm run validate-assets` → checks format, triangle count, required nodes, and rewrites the manifest.
5. `npm run dev` — the model appears in the next race. Check the console for warnings.

## 1. Technical export constraints (hard requirements)
| Rule | Karts | Kids / items / weapons / shields / obstacles |
| :-- | :-- | :-- |
| Format | `.glb` | `.glb` |
| Triangles | **< 10,000** | < 4,000 (obstacles < 6,000) |
| Origin | Chassis centre at `(0,0,0)`; **wheel bottoms touch y = -0.68** | Origin at base (kids: at the seat) |
| Forward axis | **-Z** (nose points to -Z), +Y up, 1 unit = 1 m | -Z forward |
| Size | ≈ 1.3 m wide × 2.1 m long × 1.1 m tall (excluding kid) | Obstacles 1–2.5 m tall |
| Required child nodes (karts) | `Wheel_FL`, `Wheel_FR`, `Wheel_RL`, `Wheel_RR` (pivot at wheel centre, spin axis = X) | — |
| Mount nodes (karts) | `Weapon_Mount`, `Shield_Mount`, `Driver_Seat` (empties) | — |
| Detachable cosmetics (karts) | `Cosmetic_Panel_L`, `Cosmetic_Panel_R`, `Cosmetic_Roof_Spoiler`, `Cosmetic_Bumper_Prop` — separate meshes whose origins sit at their own centres (`DamageModel.js` clones & flings them) | — |
| Materials | 1–3 simple materials per model, flat/toon colours, no transparency except shield auras | same |

Wheel wobble, suspension travel, drift slip, trick flips, shed-and-snap-back and shield auras all reuse these node names — a missing
node degrades gracefully (that effect is skipped) but a correct rig gives the full comedy.
